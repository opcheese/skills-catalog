Changelog ​

This page documents the changes in each Kimi Code CLI release.

2.5.2 (2026-11-06) ​

Bug Fixes ​

  • Fix duplicate tool declaration errors in select_tools when MCP tool definitions change.
  • web: Fix steered messages being incorrectly queued while a session is running.
  • web: Fix project creation when accessing the Web UI over HTTP.

2.5.1 (2026-11-05) ​

Bug Fixes ​

  • Fix repeated HTTP 400 errors in sessions caused by empty system messages for dynamic tool schemas.
  • Fix missing image and video previews in live and reloaded tool results.
  • Hide sessions belonging to deleted workspaces from session lists.
  • web: Fix session titles not being generated automatically after the first turn of a new session.
  • web: Fix local images not displaying when their paths contain spaces.
  • web: Fix the session info panel automatically floating over and covering chat messages in narrow layouts.
  • web: Hide stale empty implicit workspaces from the workspace list.
  • web: Fix tool call summaries repeatedly expanding and collapsing while a response is in progress.

2.5.0 (2026-11-04) ​

Features ​

  • Use /model and /effort while the agent is working; changes apply from the next turn.
  • Merge project-level Skills from the primary and remembered additional directories; the primary wins name conflicts.
  • Create remote sessions in SSH, Docker, or custom-command environments.
  • [workspace] require_trust = false treats every workspace as trusted and skips trust prompts after /reload; use it only when every workspace is trusted.

Polish ​

  • Web cross-session full-text search is off by default; set [database] global_search = true to enable it.
  • With only default_model configured, newly spawned Agent and AgentSwarm subagents use that model; the legacy force key is ignored with a warning.
  • Agent and AgentSwarm remove the implicit primary; list the main model explicitly in the pool to use it. Without [secondary_model], subagents still inherit the caller's model.

Bug Fixes ​

  • Fix several known issues and make various refinements. See the changelog on GitHub for more technical entries.

2.4.1 (2026-10-30) ​

Polish ​

  • A single file read by the agent now returns at most 100,000 characters or about 25,000 tokens, whichever comes first, instead of up to 500,000 characters; set max_chars under [read] in config.toml to raise both limits again.
  • Optimize built-in prompts.

Bug Fixes ​

  • web: Improved interactions and fixed known bugs.

2.4.0 (2026-10-28) ​

Features ​

  • Add /import-sessions and kimi import-sessions to import Claude Code and Codex sessions from the last 15 or 30 days. Run either one and choose a time range.
  • Add /provider refresh [providerId] to re-fetch provider model lists at runtime.
  • Expand streaming thinking with Ctrl-O.
  • Report main-session and subagent status to compatible terminals with OSC 7501, including pending interactions and retained results.
  • Support per-task model selection and the max_running_tasks limit in Tower, and raise its default agent concurrency limit from 16 to 256.

Polish ​

  • Plan mode can now only be enabled by the user instead of being entered automatically by the agent; every plan requires user review, Never Ask no longer approves plans automatically, and kimi -p skips default_plan_mode and cannot approve a plan in a session already in Plan mode.
  • Web sessions now unload from memory after 30 minutes idle and resume transparently on next access.
  • Improve the layout and interaction experience of some Fullscreen components, including approval option display, mouse selection, and focus switching.
  • Move todo lists into expandable transcript cards and remove the old input-area panel and Ctrl-T shortcut.
  • Improve the built-in /import-from-cc-codex skill.

Bug Fixes ​

  • Reconnect workspace MCP servers automatically with backoff when the initial connection fails or the connection drops; tune the interval with [mcp] reconnect_initial_delay_ms and reconnect_max_delay_ms.
  • Fix several known issues and make various refinements. See the changelog on GitHub for more technical entries.

2.3.3 (2026-10-26) ​

Polish ​

  • Update model switch confirmation prompts.
  • Merge the two repeated permission-mode notice lines in the swarm and goal start confirmation prompts into one sentence each.

Bug Fixes ​

  • Stop showing a failed swarm for AgentSwarm calls rejected before any subagent starts, such as while swarm mode is off; after such a rejection, the agent points you to /swarm if you asked for a swarm.
  • web: Improved interactions and fixed known bugs.

Bug Fixes ​

  • Handle tasks directly by default instead of proactively launching subagents; request delegation explicitly in your message, AGENTS.md, a skill, or an enabled multi-agent mode.

2.3.1 (2026-10-23) ​

Features ​

  • Offer to take over a session that is still in use after a retry, so sessions left locked by an exited process can be used again, and add a KIMI_CODE_SESSION_LOCK=0 switch that turns off the session lock.

Polish ​

  • Show the holding client's name in session-in-use errors.

Bug Fixes ​

  • Fix sessions occasionally remaining occupied after an application crash on macOS and Linux.
  • Fix workspace trust failures when Git Bash is unavailable on Windows.
  • web: Improved interactions and fixed known bugs.

2.3.0 (2026-10-21) ​

Features ​

  • Plugin skills are now invoked by qualified name <pluginID>:<skillName>, so same-named skills from different plugins no longer shadow each other; bare-name invocation no longer works.
  • When the same session is open in multiple clients, sending a message from another client now shows an occupancy prompt, with options to retry or cancel.
  • A session title is now generated automatically after the first turn and shown as the terminal window title.
  • Switching models mid-session now shows a confirmation dialog: start a new session, compact and continue, or continue directly.
  • Remote control now supports streaming, and the limit is raised from 10 MiB to 100 MiB.

Polish ​

  • /compact now queues while the agent is busy instead of failing with an error.
  • The session rating toggle moves from tui.toml to config.toml.
  • dangerous_command_guard = false now disables all built-in confirmation guardrails, not only dangerous commands.

Bug Fixes ​

  • Hooks now run in the session's project directory instead of the server startup directory.
  • Fix several known issues and make various refinements. See the changelog on GitHub for more technical entries.

2.2.0 (2026-10-14) ​

Features ​

  • Add an opt-in NotifyUser progress update feature (off by default): new sessions can show the agent's mid-turn progress updates. Enable it in the TUI /experiments panel.
  • Add kimi app [path] to open a new desktop chat in the current or specified directory.
  • Add sticky user message summaries in fullscreen mode: when a user message scrolls out of view, a one-line summary stays on screen, and clicking it jumps back to the original message. Fullscreen mode is enabled via the TUI mode setting in /settings, or tui_mode = "fullscreen" in ~/.kimi-code/tui.toml.

Polish ​

  • Replace user skill cards with highlighted prompts, and support Ctrl-S for skill prompts.
  • Tower mode: a message sent while the agent is running aborts the in-progress turn and runs as its own turn.
  • Show a "Shutting down" status hint while shutdown hooks run during exit; press Ctrl+C during that window to force an immediate exit instead of waiting for the hook timeout.

Bug Fixes ​

  • Fix shifted turns, lost replies, and out-of-place rendering in sessions where a UserPromptSubmit hook injects text; hook JSON output without a "message" field is no longer added to the conversation.
  • Remove the never-implemented executor = "kaos" option from MCP stdio server configuration; configs using it now fail validation at load time.
  • Cron tasks from the source session no longer fire inside a forked session.
  • Fix several known issues and make various refinements. See the changelog on GitHub for more technical entries.

0.36.0 (2026-08-13) ​

  • Upgrade the experimental subagent model setting to a model pool: the [secondary_model] section can now hold a set of candidate models with descriptions, and the main agent picks from them per spawn based on the task.

      toml
      [secondary_model]
default_model = "kimi-code/kimi-for-coding-highspeed"
[secondary_model.models]
"kimi-code/kimi-for-coding-highspeed" = "Fast and cheap — good for daily refactoring, code explanation, and small edits."
"kimi-code/k3" = "Strong at complex reasoning and deep debugging — pick it for hard problems."
