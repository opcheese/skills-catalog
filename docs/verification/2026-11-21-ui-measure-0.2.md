# Manual verification: ui-measure 0.2

Step-by-step checks of ui-measure 0.2 (builder pairs, `authoritative`, filter drop-shadows) and of the round trip
build, measure, fix, then `ui-hill-climb` round 1 reusing the pairs. Everything uses the small card fixture in
`plugins/ui-measure/test/skill-eval/`. No model is called anywhere: the pairs are a file, and the one place
where hill-climb could call a model is pointed at a script that fails if it is ever run.

How to read the tables: each command was run on 2026-11-21 and the "expect" column is what it printed.
Exit codes: `0` clean, `1` mismatches, `2` not comparable, `3` setup or usage failure.

## Setup

Install and build ui-measure (needs Node 24 and Playwright's chromium):

```bash
export REPO=<path to your clone of this repository>
cd $REPO/plugins/ui-measure
pnpm install
pnpm exec playwright install chromium
pnpm build
```

Make a work folder with a copy of the fixture, and serve it in a second terminal. Leave that terminal running;
if port 8791 is taken, pick another and use it everywhere below:

```bash
mkdir -p /tmp/um-guide/site && cd /tmp/um-guide
cp $REPO/plugins/ui-measure/test/skill-eval/{page.html,notice-card.json,font.ttf} site/
cd site && python3 -m http.server 8791 --bind 127.0.0.1
```

In the first terminal:

```bash
cd /tmp/um-guide
export UM=$REPO/plugins/ui-measure/dist/ui-measure.mjs
cat > ui-measure.config.json <<'EOF'
{"targets":{"card":{"adapter":{"kind":"url","url":"http://127.0.0.1:8791/page.html","root":"#card"},
  "viewport":[800,600],"designRootFontPx":16,"node":"site/notice-card.json"}}}
EOF
```

The fixture page has two planted defects against the design node: padding 32px where the design says 24px, and no
drop shadow.

## Happy path: measure the build

| step | command | expect |
| --- | --- | --- |
| Geometry (no design needed) | `node $UM geometry --config ui-measure.config.json --target card; echo "exit $?"` | `ui-measure clean: 0 failed, 0 not comparable; 0/0 pairs accepted, 0 dropped`, exit `0` |
| Spec with no pairs and no proposer | `node $UM spec --config ui-measure.config.json --target card --node site/notice-card.json; echo "exit $?"` | `not_comparable spec/correspondence #card: no correspondence proposer was selected`, exit `2` |

Now record the pairs the way the building agent does: one pair per design node the page implements, with
`"authoritative": true`. The file lives at `.ui-measure/pairs/<target>.json` beside the config:

```bash
mkdir -p .ui-measure/pairs
cat > .ui-measure/pairs/card.json <<'EOF'
{ "authoritative": true,
  "pairs": [
    { "nodeId": "10:1", "selector": "#card" },
    { "nodeId": "10:2", "selector": "#card h2" },
    { "nodeId": "10:3", "selector": "#card p" } ],
  "unmapped": { "design": [], "impl": [] } }
EOF
node $UM spec --config ui-measure.config.json --target card --node site/notice-card.json --json report.json; echo "exit $?"
python3 -c "import json;print(json.load(open('report.json'))['coverage'])"
```

Expected: no proposer flag is needed, the file is picked up by name. Exit `1`, with both planted defects found:

```
ui-measure mismatches: 7 failed, 0 not comparable; 3/3 pairs accepted, 0 dropped
fail spec/effects #card: DROP_SHADOW 0 4 8 rgba(0, 0, 0, 0.1) -> none
fail spec/box #card > :nth-child(1): 124,124 140x28 -> 132,132 140x28
fail spec/box #card > :nth-child(2): 124,164 272x20 -> 132,172 256x20
fail spec/padding #card: top 24px -> top 32px
fail spec/padding #card: bottom 76px -> bottom 68px
fail spec/padding #card: left 24px -> left 32px
fail spec/padding #card: right 24px -> right 32px
{'pairsProposed': 3, 'pairsAccepted': 3, 'dropped': 0, 'authoritative': True, 'rejected': []}
```

`authoritative: True` in the coverage line is how you know the builder's pairs were trusted. The two box fails
and the four padding fails are the padding defect seen from several sides; the effects fail is the missing shadow.

Fix both defects, then measure again. The first line keeps a copy of the broken page for later:

```bash
cp site/page.html site/page-broken.html
sed -i 's/padding: 32px;/padding: 24px; box-shadow: 0 4px 8px rgba(0, 0, 0, 0.1);/' site/page.html
node $UM geometry --config ui-measure.config.json --target card; echo "geometry exit $?"
node $UM spec --config ui-measure.config.json --target card; echo "spec exit $?"
```

Expected: `ui-measure clean: 0 failed, 0 not comparable; 0/0 pairs accepted, 0 dropped`, geometry exit `0`; then
`ui-measure clean: 0 failed, 0 not comparable; 3/3 pairs accepted, 0 dropped`, spec exit `0`.

A run that cannot measure is never clean. Point the config at a root that does not exist:

```bash
sed 's/"#card"/"#nope"/' ui-measure.config.json > cfg-noroot.json
node $UM spec --config cfg-noroot.json --target card --node site/notice-card.json; echo "exit $?"
```

Expected: `not_comparable spec/page #nope: root #nope not found`, exit `2`.

## Edge cases

Each case below leaves the fixed page and the pairs file untouched.

A recorded selector that matches an element rendered outside the root (for example a menu appended to `body`) is not
comparable, never dropped silently and never matched outside the root:

```bash
sed 's#</div>$#</div>\n<div id="menu">Menu</div>#' site/page.html > site/page-portal.html
sed 's/page.html/page-portal.html/' ui-measure.config.json > cfg-portal.json
cat > pairs-portal.json <<'EOF'
{"authoritative":true,"pairs":[{"nodeId":"10:1","selector":"#card"},{"nodeId":"10:2","selector":"#menu"}],"unmapped":{"design":["10:3"],"impl":[]}}
EOF
node $UM spec --config cfg-portal.json --target card --node site/notice-card.json --proposer recorded --proposal pairs-portal.json --json r-portal.json; echo "exit $?"
python3 -c "import json;print(json.load(open('r-portal.json'))['coverage']['rejected'])"
```

Expected: exit `2`, `1/2 pairs accepted, 1 dropped`, the line
`not_comparable spec/correspondence #menu: resolvable: no element inside root`, and
`[{'nodeId': '10:2', 'selector': '#menu', 'rule': 'resolvable', 'note': 'no element inside root'}]`. The padding
lines that follow (`the top padding is measured to 10:2, which has no accepted pair`) are the consequence.

An invalid CSS selector in a pairs file makes that pair not comparable; the run still completes:

```bash
cat > pairs-invalid.json <<'EOF'
{"authoritative":true,"pairs":[{"nodeId":"10:1","selector":"#card"},{"nodeId":"10:2","selector":"button[aria-label=Back"}],"unmapped":{"design":["10:3"],"impl":[]}}
EOF
node $UM spec --config ui-measure.config.json --target card --node site/notice-card.json --proposer recorded --proposal pairs-invalid.json; echo "exit $?"
```

Expected: exit `2` (not `3`), `1/2 pairs accepted, 1 dropped`, and
`not_comparable spec/correspondence button[aria-label=Back: resolvable: invalid selector`.

An authoritative pairs file with no pairs is not comparable, never clean:

```bash
echo '{"authoritative":true,"pairs":[],"unmapped":{"design":["10:1","10:2","10:3"],"impl":[]}}' > pairs-zero.json
node $UM spec --config ui-measure.config.json --target card --node site/notice-card.json --proposer recorded --proposal pairs-zero.json; echo "exit $?"
```

Expected: `not_comparable spec/correspondence #card: authoritative proposal has no pairs`, exit `2`.

A `filter` holding two drop-shadows and a blur, against a design with the matching two shadows and a layer blur,
gives no effects finding. This builds a design node with those three effects and a page that draws them with `filter`:

```bash
python3 - <<'PY'
import json
d=json.load(open("site/notice-card.json"))
doc=d["nodes"]["10:1"]["document"]
doc["effects"]=[{"type":"DROP_SHADOW","visible":True,"color":{"r":0,"g":0,"b":0,"a":0.1},"offset":{"x":0,"y":4},"radius":8},
 {"type":"DROP_SHADOW","visible":True,"color":{"r":0,"g":0,"b":0,"a":0.25},"offset":{"x":0,"y":2},"radius":4},
 {"type":"LAYER_BLUR","visible":True,"radius":4}]
json.dump(d,open("site/notice-card-fx.json","w"),indent=2)
PY
sed 's/box-shadow: 0 4px 8px rgba(0, 0, 0, 0.1);/filter: drop-shadow(0 4px 8px rgba(0, 0, 0, 0.1)) drop-shadow(0 2px 4px rgba(0, 0, 0, 0.25)) blur(4px);/' site/page.html > site/page-fx.html
sed 's/page.html/page-fx.html/' ui-measure.config.json > cfg-fx.json
node $UM spec --config cfg-fx.json --target card --node site/notice-card-fx.json --json r-fx.json; echo "exit $?"
python3 -c "
import json
for f in json.load(open('r-fx.json'))['findings']:
    if f['kind']=='effects': print(f['kind'],f['status'],f.get('expected'),f.get('actual'))"
```

Expected: `ui-measure clean: 0 failed, 0 not comparable; 3/3 pairs accepted, 0 dropped`, exit `0`, and
`effects pass DROP_SHADOW 0 4 8 rgba(0, 0, 0, 0.1); DROP_SHADOW 0 2 4 rgba(0, 0, 0, 0.25); LAYER_BLUR 4 drop-shadow(rgba(0, 0, 0, 0.1) 0px 4px 8px) drop-shadow(rgba(0, 0, 0, 0.25) 0px 2px 4px) blur(4px)`.

A malformed default pairs file is a setup error that names the file. It must not fall back to "no proposer":

```bash
mkdir -p bad/.ui-measure/pairs && cp ui-measure.config.json bad/ && cp -r site bad/site
echo '{ "pairs": [' > bad/.ui-measure/pairs/card.json
(cd bad && node $UM spec --config ui-measure.config.json --target card --node site/notice-card.json; echo "exit $?")
```

Expected: `ui-measure: /tmp/um-guide/bad/.ui-measure/pairs/card.json did not produce valid JSON`, exit `3`.

An unknown `HILL_RUNNER` is refused, naming the four valid runners. `hill-judge` needs a real PNG to get that far;
this writes a one-pixel one:

```bash
export HC=$REPO/plugins/ui-hill-climb/skills/ui-hill-climb
python3 -c "
import base64;open('shot.png','wb').write(base64.b64decode('iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=='))"
```

## Round trip: build, measure, fix, hill-climb round 1 picks up the pairs

This is the whole loop on the card. The building agent has already written `.ui-measure/pairs/card.json` (done
above). Hill-climb must use it in round 1 and must not ask a model to pair. To prove that, `HILL_PROPOSE` (the
model-backed proposer) is set to a script that leaves a marker file and fails if it is ever run.

Put back the broken page, and define the helpers (the judge file is written by hand with equal scores, as a real
`hill-judge` run would produce it):

```bash
export HILL_UI_MEASURE=$UM
cp site/page-broken.html site/page.html
sed 's/padding: 32px;/padding: 24px; box-shadow: 0 4px 8px rgba(0, 0, 0, 0.1);/' site/page-broken.html > site/page-fixed.html
mkjudge() {
  python3 - "$1/card.run1.json" <<'PY'
import json,sys
cats=["hierarchy","typography","colour","spacing","consistency","originality"]
json.dump({"label":"card","mode":"design","image":"card.png","sha256":"ab"*32,"design":{"path":"/d/x.png","sha256":"12"*32},
  "model_requested":"kimi-code/k3.1-pro","provenance":"served=unconfirmed",
  "scores":{c:6 for c in cats},"findings":[]},open(sys.argv[1],"w"))
PY
}
SUM='import json,sys; j=json.load(sys.stdin); print({k:j[k] for k in ("round","best_round","revert_to","stop","reason","measured")}, len(j["open_findings"]))'
printf '#!/bin/sh\necho called > /tmp/um-guide/model-was-called\nexit 1\n' > no-model.sh && chmod +x no-model.sh
```

Round 1 on the broken page. `hill-measure` only checks that `card.png` exists, so an empty file stands in for the
screenshot. `measure.json` names the design node but gives no `proposal`:

```bash
mkdir -p .hill/trip/round-1 && : > .hill/trip/round-1/card.png
cat > .hill/trip/measure.json <<'EOF'
{"config": "ui-measure.config.json",
 "screens": {"card": {"target": "card", "node": "site/notice-card.json"}}}
EOF
HILL_PROPOSE=$PWD/no-model.sh python3 $HC/scripts/hill-measure --run .hill/trip --round 1; echo "exit $?"
ls .hill/trip/round-1
ls model-was-called
cmp .ui-measure/pairs/card.json .hill/trip/round-1/card.proposal.json && echo "round-1 proposal is the builder's pairs file"
python3 -c "
import json;r=json.load(open('.hill/trip/round-1/card.spec.json'));print(r['verdict'],r['coverage'])"
mkjudge .hill/trip/round-1
python3 $HC/scripts/hill-score --run .hill/trip | python3 -c "$SUM"
```

Expected:

```
exit 0
card.geometry.json
card.png
card.proposal.json
card.spec.json
ls: cannot access 'model-was-called': No such file or directory
round-1 proposal is the builder's pairs file
mismatches {'pairsProposed': 3, 'pairsAccepted': 3, 'dropped': 0, 'authoritative': True, 'rejected': []}
{'round': 1, 'best_round': 1, 'revert_to': None, 'stop': False, 'reason': 'continue', 'measured': {'fails': 7, 'comparable': True, 'accepted': 3, 'guard': None}} 7
```

No `model-was-called` file means no model was asked to pair. Now the fix, and round 2 (the fixer's page change
stands in as copying the fixed page over the served one). Round 2 reuses round 1's saved pairs:

```bash
cp site/page-fixed.html site/page.html
mkdir -p .hill/trip/round-2 && : > .hill/trip/round-2/card.png
HILL_PROPOSE=$PWD/no-model.sh python3 $HC/scripts/hill-measure --run .hill/trip --round 2; echo "exit $?"
ls model-was-called
mkjudge .hill/trip/round-2
python3 $HC/scripts/hill-score --run .hill/trip | python3 -c "$SUM"
```

Expected: exit `0`, `ls: cannot access 'model-was-called'...` again, and

```
{'round': 2, 'best_round': 2, 'revert_to': None, 'stop': True, 'reason': 'no measured failures and no major deviations from the design', 'measured': {'fails': 0, 'comparable': True, 'accepted': 3, 'guard': None}} 0
```

`scores.md` in `.hill/trip/` shows the Round 1 table row `| card | geometry 0, spec 7 | mismatches | 3/3 |`.
